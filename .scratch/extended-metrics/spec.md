# 网络吞吐量与 CPU 温度扩展

## 设计状态

用户已确认完整方案，实现及本机验证已完成。

## 已确认的范围

- 本轮加入网络吞吐量与 CPU 温度两项指标。
- 两项指标均提供实时读数及数据不可用时的提示；趋势图仅在图形界面显示。
- 图形界面与终端界面同步支持，共用后台采样与快照。
- 网络显示整机上传速率与下载速率，表示实际流量。

## 已确认的网络统计口径

- 合计联网实体接口的流量，包含局域网通信。
- 不叠加回环和 VPN 虚拟接口的流量，避免重复统计。
- VPN 在实体接口上的传输开销计入流量。
- 单位自动切换 B/s、KB/s、MB/s。

## 已确认的温度口径与运行要求

- 显示单个来源明确的 CPU 代表温度，使用摄氏度。
- 来源优先级为：已验证的 CPU 封装或直接芯片温度、虚拟二极管温度、过滤二极管温度、邻近温度。仅使用来源可明确归属 CPU 的读数。
- 图形界面明确标注实际口径与传感器来源；邻近读数标为“CPU 邻近温度”，虚拟或过滤二极管读数也保留对应名称。终端按用户要求仅显示温度数字。
- 温度来源切换时断开趋势，避免把不同口径的读数连成同一连续曲线。
- 保持普通用户运行，使用现有系统框架，不增加第三方依赖。
- 来源无法确认或机型无法读取时提示“不支持”；采集失败时提示“读取失败”，缺失读数不显示为 0°C。

## 已确认的更新与趋势行为

- 沿用现有刷新控制，默认每秒更新，间隔可调。
- 图形界面的两项新增指标展示最近 60 秒趋势，按真实采样时间表达。
- 缺测处断开曲线，不把缺失数据补成零，也不连接缺口两侧的数据。
- 暂停时冻结读数；恢复后重新建立网络速率基线，避免把暂停期间的平均流量显示为当前速率。

## 已确认的界面布局

- CPU 温度使用独立卡片，包含摄氏度读数、来源名称、最近 60 秒趋势及不可用原因。
- 网络吞吐量新增独立卡片，同时展示上传、下载读数与两条趋势。
- 图形界面共十个数据卡片，沿用现有视觉样式及自适应布局。
- 终端只显示温度数字和下载、上传速率，不显示这两项指标的趋势；保留原有 CPU 占用历史及暂停、调速和进程排序操作。

## 实现边界

- 系统指标仍由后台核心采集，图形界面与终端界面读取共享快照。
- 快照发布网络速率、温度、具体来源、采样时间和有效性信息；新增指标的历史窗口由图形界面派生，终端不维护这两项指标的历史，不向核心追加展示历史数组。
- 网络按接口分别差分，并按实际单调时间差计算速率；不能先合计所有接口累计字节再做差分。
- 启动、暂停恢复、接口新增或计数回退时建立新的基线；基线不足时显示“正在采样”，不制造瞬时流量峰值。
- 接口查询成功但没有联网实体接口时显示“无网络连接”；存在有效接口且没有字节增长时显示有效零速率。接口查询失败显示“读取失败”。
- 传感器不存在、来源不明确或连接不可用时显示“不支持或不可用”；已选来源的一次读取失败显示“读取失败”。
- 暂停冻结读数和图表；恢复后的真实时间缺口保留，缺失或过期值不参与最新读数与连续趋势。
- 两项指标均不新增提权流程、外部测速、第三方运行依赖或硬件写入操作。

## 验收标准

- 图形界面有独立网络和温度卡片，终端可查看相同口径的指标；窄窗口不出现文字重叠或越界。
- 网络差分验证覆盖上传、下载、多接口汇总、虚拟接口排除、64 位累计计数、接口增删、计数回退、首次采样及暂停恢复。
- 温度验证覆盖本机所需的有符号定点解码、已有浮点编码、来源优先级、不可读来源、读取错误、无效数据及来源切换。
- 趋势验证覆盖 0.25 秒、1 秒、5 秒刷新间隔下的真实 60 秒窗口，以及采集失败、暂停和来源变化产生的断点；不得把 60 个采样点当作固定 60 秒。
- 新增指标失败时，已有 CPU、内存、磁盘、风扇与进程表继续工作。
- 运行现有核心和图形界面测试，验证常规构建及通用架构应用构建。
- 在本机普通用户环境核对实际网络读数与温度来源；未经过实机验证的机型支持范围在说明中明确记录，不把本机验证推广为全机型保证。

## 调查事实

- 本机为 Intel MacBook Air（MacBookAir8,2），macOS 12.7.6；普通用户只读探测成功。
- 本机 TCAD、TC0D 不可读；TC0E、TC0F、TC0P 可读。[传感器口径对照](https://github.com/exelban/stats/blob/master/Modules/Sensors/values.swift#L329)分别将后三者命名为虚拟 CPU 二极管、过滤 CPU 二极管和 CPU 邻近温度。
- [Apple Silicon 温度读取器](https://github.com/exelban/stats/blob/master/Modules/CPU/readers.swift#L249)存在按芯片代际选择传感器的实现；本项目尚无 Apple Silicon 实机温度验证，不能承诺所有机型可读。
- 网络应按接口分别计算累计字节的差分，再汇总速率，并使用实际时间差。接口新增、计数重置及恢复采样时需要建立有效基线；优先使用[系统提供的 64 位接口计数](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/net/if_var.h)，避免 32 位累计计数回绕。

## 验证结果

- `make test`：17 项测试全部通过，包含网络差分、温度解码与回退、真实时间窗口、缺测断点和暂停恢复。
- `make test-gui`：五种窗口关闭与退出场景及新增指标显示测试全部通过；已检查宽窄布局预览。
- `make test-tui`：网络和温度只显示读数、保留 CPU 占用历史、暂停、极窄窗口提示、放大恢复及较矮窗口最小列宽验证通过。测试揭示的旧有零尺寸缩放请求已改为使用真实伪终端尺寸。
- 使用 AddressSanitizer 与 UndefinedBehaviorSanitizer 构建并运行上述 17 项核心测试，无检查错误。
- 常规终端构建和通用架构应用构建通过；应用包含 x86_64 与 arm64，签名验证通过。
- 本机普通用户只读探测同时取得有效网络速率及 TC0E 虚拟 CPU 二极管温度，无需 sudo。读数仅为即时观测，不构成精度或全机型支持保证。
- Apple Silicon 的代表核心键依据已注明的一手来源实现，但缺少实机验证；对应限制已在 README 中记录。

## 现有约束

- 依照 ADR-0001，采集在后台核心中执行，前端读取值拷贝快照。
- 依照 ADR-0002，图形界面使用 AppKit，核心保持纯 C。
- ADR-0003 已记录十个数据卡片，网络与 CPU 温度均使用独立卡片。界面历史继续从快照派生，缺失数据不伪装为零；新增指标需要时间与有效性信息，不能直接沿用现有“60 个采样点”的数组来表示固定 60 秒窗口。
