# macmon 现代化改造 · Spec

> 底稿：多代理审计报告 `.scratch/audit-2026-10-02.md`（17 条确认缺陷 + 40 条事实条目，证据在 `.scratch/audit-evidence/`）与 2026-10-02 grilling 已定决策。

## Problem Statement

以用户视角：macmon 目前只能跑在终端里（需要真 tty），拿到的 `.app` 双击时靠"借 Terminal.app 显示"的别扭方式启动。存在一个真实的渲染卡死缺陷：把窗口缩到 12 列以下再放大，画面**永久停止刷新**，只能重启。性能上，工程内部流传的说法与实测不符（"proclist O(n²) 削掉大半"不成立）。工程层面：没有测试、采样逻辑与呈现逻辑耦合在主循环里，使图形界面无从谈起；打包与文档有若干与现实不符之处（最低系统版本声明、Gatekeeper 指引、自动化授权），分发给别人会撞上"无法验证开发者"。

## Solution

把 macmon 现代化为可分发的原生 macOS 应用，同时保留终端形态：

1. **解耦核心**：采样核心从 ncurses 前端中独立出来，核心拥有采样节奏（独立线程）并发布不可变快照；TUI 与新的 GUI 都退化为订阅者。
2. **先建测试网再动刀**：零依赖 C 单元测试覆盖核心，保留 pty 端到端回归。
3. **修复审计确认的缺陷**：High 的 resize 卡死，及 TASKS 截断、暂停陈旧、版本声明、TCC/xattr 指引等。
4. **按实测优化**：SMC 机器常量首读缓存（约 1.1ms/tick）、进程名缓存（按实测上限约 1/3）；并按审计纠正文档的不实叙述。
5. **新增 AppKit 图形界面**（`.m` 表现层 + 纯 C 核心）：v1 为主窗口仪表盘——面板与 TUI 全对齐、中文界面、只读进程表；TUI 继续保留。
6. **分发收尾**：正确的最低系统版本、自动化授权有文档有兜底、去 Terminal 依赖的启动改进。

## User Stories

1. 作为终端用户，我想让 TUI 保持现有键位、布局与信息层级不变，这样我的使用习惯不被破坏。
2. 作为终端用户，我想把窗口缩到任意小（包括 <12 列）再放大后画面能恢复，这样我不必重启进程。
3. 作为终端用户，我想在暂停时改变窗口尺寸后画面立刻按新尺寸重绘，而不是等 15 秒兜底。
4. 作为终端用户，我想在绘图行靠近边界时不被永久冻结，即使我误触了极端尺寸。
5. 作为终端用户，我想让状态行显示真实进程数，而不是恒定的 64。
6. 作为终端用户，我想在采样临时失败时看到"数据陈旧"的提示，而不是旧值冒充新值。
7. 作为无风扇机型/缺传感器的用户，我想看到"不可用"而不是假 0 RPM。
8. 作为终端用户，我想让滚动风暴类的问题（历史修复）保持不回归。
9. 作为开发者，我想有一份零依赖的 C 单元测试套件，这样重构核心时立刻知道有没有破坏行为。
10. 作为开发者，我想让采样核心有明确的公共 API（快照结构 + 采样控制），这样前端与测试都挂在同一条缝上。
11. 作为开发者，我想让核心以固定节奏在后台采样并发布快照，这样前端渲染与采样节奏互不阻塞。
12. 作为开发者，我想让 UI 偏好（间隔/排序/暂停）在重构后语义与现在完全一致。
13. 作为开发者，我想让采样间隔设置为 0.25–5 秒且无累积漂移（经审计实测已达，不得回归）。
14. 作为开发者，我想让 proclist 热点按实测优化（名称缓存等），tick 成本相比基线下降 ≥25%。
15. 作为开发者，我想让 SMC 的机器常量只读一次并缓存，每 tick 省约 1.1ms。
16. 作为开发者，我想让 `make sanitize` 的产物不再污染常规构建（已完成，需保持）。
17. 作为开发者，我想让 pty 测试夹具（driver.py）修掉已知的假阳性缺陷（区域滚动模型、CJK 宽度），这样审计/回归不再误报。
18. 作为双击启动的 Mac 用户，我想双击图标直接打开原生窗口，不经过 Terminal.app。
19. 作为 Mac 用户，我想看到中文界面。
20. 作为 Mac 用户，我想在图形界面上看到与 TUI 相同的信息面板：CPU/内存/SWAP/磁盘进度、60 秒 CPU 走势、负载/运行时间/任务数、风扇转速。
21. 作为 Mac 用户，我想让进程表可点击列头排序（只读，不提供杀进程）。
22. 作为 Mac 用户，我想让窗口自由缩放且内容自适应，没有卡死或错位。
23. 作为 Mac 用户，我想让这个应用不依赖任何第三方库，下载体积小、启动快。
24. 作为 Intel 与 Apple Silicon 两代用户，我想同一个分发包在两代芯片上都能运行（universal）。
25. 作为 macOS 12 及以上的用户，我想安装包声明的最低系统版本与实际二进制一致（12.0）。
26. 作为接收分发的用户，我想拿到正确的 Gatekeeper 放行指引（含递归的 `xattr -dr`），并提前知道首次打开会看到什么（包括自动化授权弹窗）。

## Implementation Decisions

1. **平台与依赖**：仅使用系统框架（Cocoa/IOKit/Mach/ncurses），零第三方依赖；universal（x86_64 + arm64）；最低 macOS 12；本轮 ad-hoc 签名，Developer ID + 公证后置（待开发者账号）。
2. **双前端架构**：新增"采样核心"模块（拥有采样线程与节奏参数），向订阅者发布**不可变快照**；TUI 与 GUI 都是订阅者，主线程永不采样。UI 偏好（间隔/排序/暂停）保留在状态模型，经核心生效。
3. **核心 API 形态**：推模型。快照包含全部面板数据（系统指标 + 进程表数组 + CPU 历史序列）；采样间隔为核心参数；暂停使核心停采但保留最后快照（由前端继续渲染）。
4. **缺陷修复**（按审计编号）：

   - #1 resize 卡死：`ui_draw` 的尺寸早退路径必须仍然触碰屏幕/触发 `resizeterm`，否则 ncurses 不再消化 SIGWINCH；修复后 <12 列→放大必须恢复渲染。
   - #2 TASKS 显示真实可见进程数（不受 64 行截断影响）。
   - #3 暂停时窗口尺寸变化：key 输入循环需在无采样时也感知 resize 并立即重绘。
   - #4 构建加入 `-mmacosx-version-min=12.0`，使二进制 minos 与 Info.plist 声明一致。
   - #5 启动器：Info.plist 补自动化用途说明；授权失败给出用户可理解的兜底提示；README 补充 TCC 内容。
   - #6 README 的放行指引改为递归（`xattr -dr`）。
   - #7 sysinfo 返回值检查：失败时保留旧值但标注"陈旧"，且不把旧值再次推入历史序列。
   - #8 SMC 检查 result/status 字节：非零即视为读取失败（缺失传感器不再伪装成 0）。
   - #9 `make sanitize` 隔离产物（已完成）；#10 run-macmon 的悬空 SKILL.md 引用处理；#11 README external_page_count 叙述修正。
5. **性能**：SMC 常量（风扇 min/max、数量）首读缓存；proclist 进程名缓存（预期收益上限约 1/3，以实测为准）；`proc_pidinfo` 无法低成本消除、不做；README 性能叙述按审计纠偏（O(n²) 仅占 2–4%）。
6. **GUI v1（AppKit）**：`.m` 表现层 + 纯 C 核心；主窗口仪表盘，面板与 TUI 全对齐（含 60 秒 CPU 走势）；中文文案；进程表只读、可点击列头排序；窗口自由缩放自适应；无菜单栏常驻（v1.5）；表现层可访问同一快照 API。
7. **TUI 保留**：键位、布局、信息层级不变；resize 修复在 TUI 层完成。
8. **测试夹具**：修复 driver.py 的两类假阳性（区域滚动/DECSTBM 支持、CJK 宽度计数），作为 M1 工程卫生的一部分。
9. **工程流程**：按本地 `.scratch` 跟踪制拆票；先测试网后重构；按里程碑提交。

## Testing Decisions

- **好测试的标准**：只测外部行为——核心的公开 API 输入/输出（快照内容、节奏、暂停语义）；TUI 的 pty 字节流行为（渲染恢复、输出有界）。不测实现细节（内部函数、结构体布局、私有状态）。
- **唯一主缝（seam）**：**采样核心的快照 API**。两个前端与全部核心单测都挂在这一条缝上——理想缝数=1。现有最高缝优先：TUI 已由 pty 驱动占据端到端层，GUI 复用同一 API 而不新增自动化缝。
- **被测模块**：采样核心（节奏、间隔、暂停、快照完整性）；proclist/SMC 的纯计算部分（经核心 API 触达）；TUI 端到端（关键回归：<12 列→放大恢复、暂停 resize、scroll-storm 有界）。
- **新缝**：`tests/` 目录 + 零依赖断言宏 + `make test`；测试直接链接核心源文件（不经过 TUI/GUI）。
- **先行先例**：pty 驱动（driver.py，已在用）；审计中的复现命令（如 `size 11 6 → size 100 30`）转正为回归用例；`make sanitize` 跑测试。
- **GUI 的测试边界**：v1 不做 GUI 自动化（人工验收清单：双击启动、面板齐全、中文、排序、缩放）；其数据正确性由核心单测覆盖。
