# ADR-0003: GUI 数据卡片的历史与视觉边界

## 状态

已接受

## 决策

GUI 使用八个数据卡片展示四项资源和四项运行状态。资源卡使用最近的快照序列表达资源趋势；负载、进程数量和风扇使用符合其含义的状态变化表达；运行时间使用持续时间表达，不伪造周期趋势。

GUI 从核心发布的不可变快照中派生卡片历史，按快照序列去重并限制保留窗口。核心快照 API 不因为 GUI 图表增加资源历史字段，TUI 与核心的公共边界保持不变。

缺少、陈旧或无传感器数据保留为明确状态，卡片图表显示相应空态，不把缺失数据转换成零值。

## 原因

核心快照是项目唯一的测试缝和两个前端共享的数据边界。将展示历史留在 GUI 可以避免扩展核心 API，同时保证每个图表仍来自真实快照。不同状态的时间含义不同，统一绘制成折线会让运行时间等信息产生误导。

## 备选方案

- 扩展核心快照，为所有资源发布独立历史数组：会扩大公共 API 和同步数据量。
- 只绘制当前值进度条：无法表达用户要求的变化趋势。
- 将所有状态统一画成折线：运行时间等单调或离散状态不适合这种表达。
